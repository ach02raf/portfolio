RAG Document Assistant

Document-grounded RAG assistant with page-level citations, LLM reranking and a FastAPI + Next.js stack.

A document-grounded assistant built with Next.js, FastAPI and PostgreSQL/pgvector. It extracts text from PDF, DOCX, TXT and MD files, splits it page by page, embeds it with OpenAI text-embedding-3-small, then retrieves, LLM-reranks and answers with deduplicated page-level sources through a documented REST API.

Pipeline + answer with page sources

What I built

  • Accepts PDF, DOCX, TXT and MD uploads with a 50 MB limit and explicit format validation.
  • Preserves exact page numbers during pypdf/python-docx extraction and RecursiveCharacterTextSplitter chunking.
  • Embeds chunks in batches of 100 with text-embedding-3-small and stores them in a pgvector HNSW cosine index.
  • Retrieves 20 candidates, reranks them with gpt-4o-mini structured scoring, then sends the top 5 passages to the answer model.
  • Returns structured answers with deduplicated document, page, excerpt and similarity-score sources; when context is insufficient, the model leaves sources empty and says so.
  • Exposes /health, document list/upload/delete and /api/chat endpoints with a Next.js 14 chat UI and document selector.

    Runs PostgreSQL/pgvector, the FastAPI backend and the Next.js frontend as three Docker Compose services.

  2. 02

    Creates the vector extension, tables and HNSW index on startup with a bounded psycopg connection pool.

  3. 03

    Keeps model choice, chunk size, retrieval depth, reranking, CORS and upload limit in a documented .env template.

  4. 04

    Uses Pydantic settings and response schemas so configuration errors and API contracts fail early.

  5. 05

    Adds health checks, upload-size validation and explicit 400/413/500 error paths for operational clarity.

  6. 06

    Documents local and Docker workflows, curl examples and troubleshooting steps in the repository README.
