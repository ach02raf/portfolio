Real‑Time Messaging with GraphQL Subscriptions + Redis

Mohamed Achraf Ben Fredj

Why isolate messaging

Real‑time workloads have unique scaling, ordering, and reliability needs. A dedicated microservice improves performance and team velocity.

Core architecture

GraphQL over HTTP for queries/mutations; Subscriptions (WebSockets) for realtime. Redis Pub/Sub for live fanout; Redis Streams + DB for durable history.

Pub/Sub vs Streams

Pub/Sub is low latency and ephemeral; Streams are ordered and durable with backpressure and replay. Use both: Streams for persistence, Pub/Sub for online fanout.

Backpressure and ordering

Persist first, ack after durable write. Use Stream IDs for per‑conversation order and idempotency keys to prevent duplicates.

Security and abuse controls

Authorize on subscribe/publish, rate‑limit sends, encrypt in transit/at rest, and apply quotas per user/org.
